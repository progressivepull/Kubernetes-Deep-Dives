# Explore the Helm Chart Directories and Files

## Lesson overview

A chart generated with `helm create first-chart` includes metadata, default configuration, dependency storage, and Kubernetes manifest templates. Helm renders templates with chart information and configured values to produce Kubernetes resources.

## Open the chart

```bash
cd helm-course/first-chart
ls -la
```

Open this folder in your preferred text editor to examine its contents.

## Typical chart structure

```text
first-chart/
├── Chart.yaml
├── values.yaml
├── charts/
└── templates/
    ├── _helpers.tpl
    ├── NOTES.txt
    ├── deployment.yaml
    ├── service.yaml
    ├── serviceaccount.yaml
    ├── ingress.yaml
    └── hpa.yaml
```

*The exact generated files vary with Helm version.*

## Key files and directories

| Path | Purpose |
|---|---|
| `Chart.yaml` | High-level chart metadata: API version, name, description, chart type, chart version, and application version. |
| `values.yaml` | Default configurable settings such as container image, service account, service type, and service port. |
| `charts/` | Stores packaged subcharts used as dependencies. |
| `templates/` | Contains templates rendered into Kubernetes resource manifests. |
| `templates/NOTES.txt` | Renders post-install guidance displayed to the user. |
| `templates/_helpers.tpl` | Defines reusable named template helpers, including resource-name generation. |
| `templates/deployment.yaml` | Describes a Kubernetes Deployment. |
| `templates/service.yaml` | Describes a Kubernetes Service. |
| `templates/serviceaccount.yaml` | Describes a ServiceAccount. |
| `templates/ingress.yaml` | Describes an Ingress, when enabled. |
| `templates/hpa.yaml` | Describes a HorizontalPodAutoscaler, when enabled. |

## How Helm templating works

Helm templates use double curly braces, for example:

```yaml
spec:
  type: {{ .Values.service.type }}
  ports:
    - port: {{ .Values.service.port }}
```

The corresponding defaults in `values.yaml` might be:

```yaml
service:
  type: ClusterIP
  port: 80
```

Helm renders those expressions into a Kubernetes manifest containing `type: ClusterIP` and `port: 80`.

- `.Values` accesses configuration values supplied to the chart.
- Named helpers defined in `_helpers.tpl` can generate consistent resource names.
- The example's fullname helper keeps names within the Kubernetes DNS label limit of 63 characters.
- `Chart.yaml` metadata is accessible in templates through `.Chart`.

## Inspect rendered output

Run from the directory containing `first-chart/`:

```bash
helm template my-release ./first-chart
```

This prints rendered Kubernetes YAML without installing the chart. To override a default:

```bash
helm template my-release ./first-chart --set service.type=NodePort
```

## Key takeaways

1. `Chart.yaml` defines what the chart is.
2. `values.yaml` defines default settings that users can override.
3. `charts/` holds subchart dependencies.
4. `templates/` converts configuration into Kubernetes resource definitions.
5. `_helpers.tpl` centralizes reusable template logic.
6. `NOTES.txt` provides post-install information.
