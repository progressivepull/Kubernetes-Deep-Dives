# Create a New Helm Chart from the Command Line

## Lesson Summary

This lesson introduces how to create your own **Helm chart** instead of only installing existing charts such as `cert-manager`. The Helm CLI can automatically generate a starter chart with a consistent directory structure and boilerplate files for deploying an application to Kubernetes.

## Step-by-Step Instructions

### 1. Create a working directory

```bash
mkdir helm-course
cd helm-course
```

### 2. Generate a new Helm chart

```bash
helm create first-chart
```

This creates a new directory named `first-chart` containing a starter Helm chart.

### 3. Inspect the generated files

```bash
ls first-chart
```

The instructor describes **two files and two directories** at the top level of the generated chart. A typical chart includes:

```text
first-chart/
├── Chart.yaml       # Chart metadata
├── values.yaml      # Default configuration values
├── charts/          # Optional dependency charts
└── templates/       # Kubernetes manifest templates
```

The `templates/` directory normally contains several additional starter files. Exact contents can vary with the Helm version.

## Key Concepts

- **Helm chart:** A package of templates and configuration used to deploy an application on Kubernetes.
- **`helm create`:** Generates a boilerplate chart, saving time and providing a predictable structure.
- **`Chart.yaml`:** Defines chart metadata such as name and version.
- **`values.yaml`:** Holds configurable defaults used by templates.
- **`templates/`:** Contains templates that render into Kubernetes resource manifests.
- **`charts/`:** Can hold dependent charts.

## Command Reference

| Command | Purpose |
|---|---|
| `mkdir helm-course` | Create a workspace directory. |
| `cd helm-course` | Enter the workspace. |
| `helm create first-chart` | Generate a starter Helm chart. |
| `ls first-chart` | List the generated top-level contents. |

## Main Takeaway

Use **`helm create <chart-name>`** to quickly scaffold a custom Helm chart. The generated files provide a starting point that you can customize before deploying your application to Kubernetes.
