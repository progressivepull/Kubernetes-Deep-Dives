# Roll Back a Helm Release

## Lesson overview

Helm can restore an earlier release revision when a deployment introduces a problem. A rollback uses the configuration and chart resources stored for a previous release revision, helping recover from an unsuccessful change.

## Step-by-step instructions

### 1. Inspect release history

```bash
helm history first-chart
```

The history table includes revision number, deployment date, status, chart version, application version, and a description. Identify the revision you want to restore.

### 2. Roll back to the previous revision

```bash
helm rollback first-chart
```

When no revision is specified, Helm rolls back to the previous release revision. Check the history to confirm the result:

```bash
helm history first-chart
```

In the lesson, this created revision **4**, with a description indicating a rollback to revision **2**.

### 3. Roll back to a specific older revision

To restore revision 1:

```bash
helm rollback first-chart 1
```

Then verify:

```bash
helm history first-chart
helm status first-chart
```

In the lesson, the rollback to revision 1 created a new revision **5**. A rollback does **not** erase the intervening revision history; it creates a new revision that restores the selected prior release state.

## Command reference

| Command | Purpose |
|---|---|
| `helm history first-chart` | Show the release's revision history |
| `helm rollback first-chart` | Roll back to the previous revision |
| `helm rollback first-chart 1` | Restore revision 1 |
| `helm status first-chart` | Inspect current release status |
| `kubectl get pods` | Check Kubernetes workloads after rollback |

## Important considerations

- The release name is `first-chart`; revision numbers identify points in that release's history.
- Check application health after rollback, not just whether Helm reports success.
- Rollback restores Helm-managed resources, but does not necessarily reverse external side effects, database migrations, or persistent data changes.
- If the release is in a non-default namespace, include `--namespace <namespace>` in Helm commands.

## Key takeaways

1. Use `helm history` to inspect available revisions.
2. Use `helm rollback` without a revision to restore the previous revision.
3. Supply a revision number to restore a specific older release state.
4. Each successful rollback becomes a **new** release revision.
5. Validate Kubernetes resources and application behavior after rolling back.
