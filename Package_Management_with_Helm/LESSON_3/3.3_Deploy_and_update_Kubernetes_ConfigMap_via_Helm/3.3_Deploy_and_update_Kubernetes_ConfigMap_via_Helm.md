# Deploy and Update a Kubernetes ConfigMap Using Helm

## Lesson Summary

A **ConfigMap** is a Kubernetes resource that stores **non-sensitive configuration data** as key-value pairs, such as port numbers and environment names. This lesson demonstrates how to create a ConfigMap template in a Helm chart, install it in a cluster, verify its contents, and update it with `helm upgrade`.

## 1. Prepare the Helm Chart

Starting inside the `first-chart` chart directory, the instructor removes the generated `templates/` directory and creates a new, empty one to focus exclusively on the ConfigMap.

> **Caution:** Deleting `templates/` removes all the existing deployment, service, and other templates. Do this only in a disposable learning chart, not an existing production chart.

```bash
cd helm-course/first-chart
rm -rf templates
mkdir templates
```

Create `templates/configmap.yaml`.

## 2. Define the ConfigMap

```yaml
apiVersion: v1
kind: ConfigMap
metadata:
  name: first-chart-configmap
data:
  port: "8080"
```

- `apiVersion: v1`: Kubernetes API version for ConfigMaps.
- `kind: ConfigMap`: Resource type.
- `metadata.name`: Name of the ConfigMap.
- `data`: String key-value pairs available to workloads that reference the ConfigMap.

**Note:** ConfigMap `data` values must be strings; quote numeric and boolean-looking values.

## 3. Install the Chart

From the `first-chart` directory:

```bash
helm install first-chart .
```

- `first-chart` is the Helm **release name**.
- `.` tells Helm to install the chart from the **current directory**.
- Without `--namespace`, Helm uses the namespace in the current Kubernetes context (commonly `default`).

## 4. Verify the ConfigMap

List ConfigMaps:

```bash
kubectl get configmap
```

Inspect the ConfigMap:

```bash
kubectl describe configmap first-chart-configmap
```

Expected configuration:

```text
port: 8080
```

## 5. Update the ConfigMap

Edit `templates/configmap.yaml` to add another key:

```yaml
apiVersion: v1
kind: ConfigMap
metadata:
  name: first-chart-configmap
data:
  port: "8080"
  allowTesting: "true"
```

Apply the chart changes to the existing release:

```bash
helm upgrade first-chart .
```

Verify the updated resource:

```bash
kubectl describe configmap first-chart-configmap
```

The ConfigMap now contains two entries:

```text
port: 8080
allowTesting: true
```

## Command Reference

| Command | Purpose |
|---|---|
| `helm install first-chart .` | Install the local Helm chart as a new release. |
| `kubectl get configmap` | List ConfigMaps in the current namespace. |
| `kubectl describe configmap first-chart-configmap` | Inspect ConfigMap details and values. |
| `helm upgrade first-chart .` | Apply chart changes to the installed release. |
| `helm list` | Show installed Helm releases. |
| `helm uninstall first-chart` | Optional: uninstall the practice release. |

## Key Takeaways

1. ConfigMaps hold **non-sensitive** application configuration; use Kubernetes Secrets for sensitive values.
2. Helm renders resource manifests placed in a chart's `templates/` directory.
3. `helm install` creates a release and its Kubernetes resources.
4. `kubectl get` and `kubectl describe` help confirm that resources were created correctly.
5. `helm upgrade` updates resources after modifying the chart templates.
6. A ConfigMap update does **not** automatically guarantee that an application reloads its configuration; behavior depends on how the application consumes it.
