# Helm: Get Information About Your Chart with `helm show`

## 1. Overview

Third-party Helm charts often need customization for a Kubernetes cluster. The `helm show` command lets you inspect a chart's metadata, documentation, and default configuration before changing anything.

## 2. Common `helm show` Commands

| Command | Purpose |
|---|---|
| `helm show chart` | Display metadata from `Chart.yaml`. |
| `helm show values` | Display default values from `values.yaml`. |
| `helm show readme` | Display the chart README. |
| `helm show all` | Display combined chart information. |
| `helm show crds` | Display CRDs packaged in the chart, if any. |

Syntax:

```bash
helm show chart <repository/chart-name>
```

A chart reference is different from a Helm *release name*. For example, `cert-manager` may be the installed release name, while `jetstack/cert-manager` identifies a chart in the configured Jetstack repository.

## 3. Inspect Chart Metadata

```bash
helm show chart jetstack/cert-manager
```

The output can include `apiVersion`, `name`, `description`, chart `version`, `appVersion`, `keywords`, `maintainers`, and `annotations`.

If you run `helm show chart` without an argument, Helm reports that a chart reference is required. Using just `cert-manager` may also fail when Helm cannot resolve it as a chart path or repository reference.

## 4. Inspect Default Values

```bash
helm show values jetstack/cert-manager
```

This prints the chart's default `values.yaml` content. These settings influence the Kubernetes resources generated from the chart's templates.

Save the output for easier inspection:

```bash
helm show values jetstack/cert-manager > values.yaml
```

The `>` operator writes command output to a file, replacing that file if it already exists.

Open it in an editor:

```bash
code values.yaml
# Or on Ubuntu:
nano values.yaml
```

## 5. Configuration Settings Mentioned in the Lesson

| Setting | Purpose |
|---|---|
| `rbac` | Controls Kubernetes role-based permissions. |
| `priorityClassName` | Selects a scheduling priority class, if configured. |
| `livenessProbe` | Helps Kubernetes detect a container that needs restarting. |
| `readinessProbe` | Helps Kubernetes decide whether a container is ready for traffic. |

The instructor found RBAC enabled and liveness/readiness probe defaults in the chart version demonstrated. **Defaults vary by chart version**; inspect the version you intend to use.

## 6. Customize a Release

For most projects, keep a small override file rather than editing a full copy of the defaults. Only use keys supported by your chart version.

For example, a *generic* chart might accept:

```yaml
replicaCount: 2
resources:
  requests:
    cpu: 100m
    memory: 128Mi
```

This example is **not a guaranteed cert-manager configuration**.

Apply reviewed overrides to an installed release:

```bash
helm upgrade cert-manager jetstack/cert-manager \
  --namespace cert-manager \
  --version <chart-version> \
  --values values.yaml
```

Replace `<chart-version>` with a real chart version. Check version compatibility and chart-specific instructions before upgrading. Editing a local values file alone does not change the cluster.

## 7. Chart vs. Release

| Concept | Example | Meaning |
|---|---|---|
| Chart | `jetstack/cert-manager` | Installable package and templates. |
| Release | `cert-manager` | Installed instance of that chart. |
| Values | `values.yaml` | Configuration used to render templates. |

Inspect values for an existing release:

```bash
helm get values cert-manager -n cert-manager
helm get values cert-manager -n cert-manager --all
```

The `--all` form includes computed values, including defaults.

## 8. Key Takeaways

1. `helm show chart` reveals chart metadata.
2. `helm show values` reveals default configuration.
3. Chart references and installed release names are not interchangeable.
4. Redirect output to a YAML file to inspect it comfortably.
5. RBAC and health probes are important settings to review.
6. Use a small override file when practical.
7. Apply changes with `helm upgrade`, after checking supported values and versions.
