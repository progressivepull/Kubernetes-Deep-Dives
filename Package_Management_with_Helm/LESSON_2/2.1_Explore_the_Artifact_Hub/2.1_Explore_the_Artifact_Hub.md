# Helm: Explore the Artifact Hub

## Overview

Artifact Hub is a catalog for discovering Helm charts and other cloud-native packages. Teams use Helm to install trusted third-party applications and deploy their own microservices.

**Lesson goal:** Find a trustworthy cert-manager chart, install it in Kubernetes, and verify the resources it creates.

## 1. What is cert-manager?

cert-manager is a Kubernetes add-on that helps automate issuing, renewing, and managing TLS certificates. Automating certificate management reduces manual work and helps prevent certificate-expiration outages.

## 2. Find a trustworthy chart

1. Visit [Artifact Hub](https://artifacthub.io/).
2. Search for `cert-manager`.
3. Filter to **Helm charts**.
4. Check the official-project designation, verified publisher, and CNCF affiliation where applicable.
5. Review the chart's documentation and version before installing.

A familiar name alone does not prove that a chart is trustworthy.

## 3. Install cert-manager (training walkthrough)

> **Version note:** The video uses cert-manager **v1.16.1**, which is a historical training example, not necessarily the current release. For new installations, use the [official cert-manager Helm instructions](https://cert-manager.io/docs/installation/helm/) for the version you choose. CRD installation procedures vary by version; do not combine incompatible methods.

### Step 1: Install matching Custom Resource Definitions (CRDs)

The instructor first applies a CRD manifest using `kubectl`. Get the **exact manifest URL for your chosen version** from the official documentation:

```bash
kubectl apply -f <matching-cert-manager-crd-manifest-url>
```

CRDs extend Kubernetes with cert-manager-specific resource types. The placeholder above is not an executable URL.

### Step 2: Add the Jetstack Helm repository

```bash
helm repo add jetstack https://charts.jetstack.io
helm repo list
helm repo update
```

`helm repo list` confirms that Helm knows about the repository.

### Step 3: Create the namespace

```bash
kubectl get namespaces
kubectl create namespace cert-manager
```

If the namespace already exists, skip the creation command.

### Step 4: Install the chart

For the video's **v1.16.1** example, assuming the matching CRDs were installed as instructed:

```bash
helm install cert-manager jetstack/cert-manager \
  --namespace cert-manager \
  --version v1.16.1
```

| Argument | Meaning |
|---|---|
| `helm install` | Install a chart as a Helm release. |
| `cert-manager` | Release name (customizable). |
| `jetstack/cert-manager` | Repository and chart name. |
| `--namespace cert-manager` | Target namespace. |
| `--version v1.16.1` | Version used in the video. |

**Alternative:** Add `--create-namespace` to the `helm install` command to have Helm create the namespace if necessary.

## 4. Troubleshoot a missing namespace

If installation fails because the namespace does not exist:

```bash
kubectl get ns
kubectl create ns cert-manager
```

Then retry the appropriate installation command. Check other error messages before assuming the namespace is the cause.

## 5. Verify the installation

```bash
helm list -n cert-manager
helm status cert-manager -n cert-manager
kubectl get all -n cert-manager
```

The lesson shows that cert-manager creates resources including **Pods, Services, Deployments, and ReplicaSets**. Its **CRDs** are cluster-scoped, so they are not shown by `kubectl get all -n cert-manager`.

To inspect CRDs separately:

```bash
kubectl get crds
```

## 6. Why use Helm?

Without Helm, deploying a complex application can require applying and maintaining numerous YAML manifests manually. Helm groups related resources into a chart and manages them as a release, simplifying installation, upgrades, and rollbacks.

## Key takeaways

- Artifact Hub helps discover reusable Kubernetes packages.
- Evaluate publishers and documentation before trusting a chart.
- cert-manager automates TLS certificate management.
- CRDs add custom resource types to Kubernetes.
- `helm repo add` registers a chart repository.
- `helm install` deploys a chart as a named release.
- `helm list`, `helm status`, and `kubectl get all` help verify a deployment.
- Always follow version-matched installation instructions.
