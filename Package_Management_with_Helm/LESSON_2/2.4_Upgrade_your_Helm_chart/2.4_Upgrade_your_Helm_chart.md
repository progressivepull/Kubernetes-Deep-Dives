# Helm: Upgrade Your Helm Chart — Summary

## 1. Why Helm Upgrades Matter

Operations and platform engineers use Helm to manage the lifecycle of applications deployed to Kubernetes. The `helm upgrade` command can update an installed release to a different chart version or apply configuration changes.

**Key point:** `helm upgrade` can also install an *older* chart version. This is a chart downgrade performed through Helm's upgrade command.

## 2. Check the Installed Release

```bash
helm ls --namespace cert-manager
```

The output includes the release name, namespace, revision, status, **chart version**, and **application version**.

| Version | Meaning |
|---|---|
| Chart version | Version of the Helm chart package and its templates/configuration. |
| App version | Version of the underlying application packaged by the chart. |

These versions sometimes match, but they do not have to.

## 3. Why Change Chart Versions?

A newer chart may introduce changes that affect other services or cluster behavior. Test upgrades in a **staging cluster** before rolling them out to production.

The video demonstrates moving cert-manager from chart version **v1.16.1** to **v1.15.3** to test an earlier version. These are historical lesson versions, not current release recommendations.

Find available chart versions in [Artifact Hub](https://artifacthub.io/) or in the chart repository:

```bash
helm repo update
helm search repo jetstack/cert-manager --versions
```

## 4. Understand the `helm upgrade` Syntax

```bash
helm upgrade RELEASE CHART [flags]
```

| Argument | Example | Purpose |
|---|---|---|
| `RELEASE` | `cert-manager` | Name of the installed Helm release. |
| `CHART` | `jetstack/cert-manager` | Repository-qualified chart name. |
| `--version` | `v1.15.3` | Desired chart version. |
| `--namespace` | `cert-manager` | Namespace containing the release. |

### Lesson example: change to chart version v1.15.3

```bash
helm upgrade cert-manager jetstack/cert-manager \
  --version v1.15.3 \
  --namespace cert-manager
```

**Caution:** This is a demonstration, not a recommendation to downgrade a live cert-manager deployment. Review version compatibility, CRDs, release notes, backups, and supported downgrade procedures first. Helm does not automatically guarantee that CRD changes or application data are safely reversible.

## 5. Troubleshoot the Missing Namespace

In the video, the first upgrade fails because the namespace was omitted. Helm searches the wrong namespace and cannot find the intended deployed release.

Use:

```bash
helm ls --namespace cert-manager
helm upgrade cert-manager jetstack/cert-manager \
  --version v1.15.3 \
  --namespace cert-manager
```

## 6. Verify the Upgrade

Check the Helm release:

```bash
helm ls --namespace cert-manager
helm status cert-manager --namespace cert-manager
helm history cert-manager --namespace cert-manager
```

Inspect the Kubernetes resources:

```bash
kubectl get all --namespace cert-manager
```

During a chart version change, some resources may be replaced while others stay unchanged:

| Resource | Possible behavior |
|---|---|
| Pods | New pods may be created as workloads roll out. |
| ReplicaSets | New ReplicaSets may appear while older ones remain in history. |
| Deployments | Existing Deployment objects may remain while their pod templates change. |
| Services | May remain unchanged if the service configuration did not change. |

**Note:** Fresh pod ages alone do not prove an upgrade succeeded. Confirm the Helm release version and check workload readiness.

## 7. Key Takeaways

1. Helm manages application releases across their lifecycle.
2. `helm ls -n cert-manager` shows installed releases and chart/application versions.
3. Chart version and application version are distinct concepts.
4. `helm upgrade` can move a release to a newer **or older** chart version.
5. `--version` selects a specific chart version.
6. `--namespace` targets the namespace where the release exists.
7. `kubectl get all -n cert-manager` helps inspect Kubernetes resource changes.
8. Some resources change during an upgrade while others remain unchanged.
9. Test changes in staging and review compatibility before making production changes.

## 8. Next Lesson

Practice installing and updating a Helm chart independently.

**Bottom line:** `helm upgrade` helps operators change chart versions and configuration while tracking releases in Kubernetes. Always verify the result and assess downgrade risks.
