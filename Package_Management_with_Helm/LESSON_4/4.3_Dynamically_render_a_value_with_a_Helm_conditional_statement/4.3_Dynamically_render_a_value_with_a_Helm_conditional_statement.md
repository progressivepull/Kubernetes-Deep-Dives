# Helm: Dynamically Render a Value with a Conditional Statement

## Summary

Helm's Go-based templating engine supports `if`, `else`, and `end` directives. These allow Kubernetes manifests to render different configuration values depending on settings in `values.yaml`.

In this lesson, a ConfigMap enables testing in **staging** and disables it in **production**.

## 1. Helm conditional syntax

```yaml
{{ if CONDITION }}
  # Render when true
{{ else }}
  # Render when false
{{ end }}
```

The `eq` function compares values for equality.

## 2. Define the environment

In `values.yaml`:

```yaml
env: staging
```

For production, use `env: production`.

## 3. Conditional ConfigMap

In `templates/configmap.yaml`:

```yaml
apiVersion: v1
kind: ConfigMap
metadata:
  name: first-chart-configmap
data:
  environment: {{ .Values.env | quote }}
  {{- if eq .Values.env "staging" }}
  allowTesting: "true"
  {{- else }}
  allowTesting: "false"
  {{- end }}
```

| Expression | Meaning |
|---|---|
| `{{ if ... }}` | Start conditional rendering |
| `eq` | Test equality |
| `.Values.env` | Read `env` from chart values |
| `{{ else }}` | Alternative branch |
| `{{ end }}` | Close conditional |
| `{{-` | Trim whitespace to the left |

ConfigMap `data` values are strings, so `"true"` and `"false"` are quoted.

## 4. Preview the rendered YAML

```bash
helm template first-chart .
```

With `env: staging`:

```yaml
data:
  environment: "staging"
  allowTesting: "true"
```

With `env: production`:

```yaml
data:
  environment: "production"
  allowTesting: "false"
```

## 5. Test without editing values.yaml

```bash
helm template first-chart . --set env=staging
helm template first-chart . --set env=production
```

Upgrade an existing release:

```bash
helm upgrade first-chart . --set env=production
```

**Note:** The `else` branch also disables testing for missing or unexpected environment values. Consider validating allowed environments if this is important for deployment safety.

## Key takeaways

- Helm conditional directives generate environment-specific manifests.
- `eq .Values.env "staging"` checks the configured environment.
- `helm template` previews output without deploying it.
- `--set` overrides a chart value for a single command.
- One Helm chart can support both staging and production configurations.

**Main concept:** Use Helm conditional statements to control Kubernetes configuration dynamically from chart values.
