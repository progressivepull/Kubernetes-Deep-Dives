# Helm: Dynamically Generate Multiple Versions of a ConfigMap

## Chapter 4 Challenge Solution — Summary

### Overview

This lesson demonstrates how to use **Helm conditional statements** to dynamically configure a Kubernetes ConfigMap based on the deployment environment. Instead of maintaining separate ConfigMap files for staging and production, Helm uses one template to select the correct port.

## 1. Challenge Objective

| Environment | Port |
|---|---|
| Staging | `8080` |
| Production | `3000` |
| Any other value | `3000` |

## 2. Configure `values.yaml`

For production:

```yaml
environment: production
```

For staging:

```yaml
environment: staging
```

## 3. Create a Conditional ConfigMap Template

File: `templates/configmap.yaml`

```yaml
apiVersion: v1
kind: ConfigMap
metadata:
  name: {{ .Release.Name }}-config
data:
  environment: {{ .Values.environment | quote }}
  {{- if eq .Values.environment "staging" }}
  port: "8080"
  {{- else }}
  port: "3000"
  {{- end }}
```

### Explanation

- `{{ .Values.environment }}` reads the environment from `values.yaml`.
- `if eq` checks whether the environment equals `staging`.
- `port: "8080"` is selected for staging.
- `else` selects port `3000` for production or any other value.
- `end` closes the conditional statement.
- `quote` ensures the environment is rendered as a string.

## 4. Test the Helm Template

From the Helm chart directory, run:

```bash
helm template first-chart .
```

Expected ConfigMap data for production:

```yaml
data:
  environment: "production"
  port: "3000"
```

Expected ConfigMap data for staging:

```yaml
data:
  environment: "staging"
  port: "8080"
```

`helm template` renders Kubernetes YAML locally without deploying to a cluster.

## 5. Key Takeaways

- Helm conditionals support environment-specific configuration.
- One ConfigMap template can serve multiple environments.
- `values.yaml` controls the generated configuration.
- `helm template` lets you inspect output before deployment.
- Correct YAML indentation matters.
- ConfigMap `data` values must be strings, so port numbers are quoted.

## 6. Useful Commands

| Command | Purpose |
|---|---|
| `helm template first-chart .` | Render the chart locally |
| `helm lint .` | Check for common chart issues |
| `helm template first-chart . --set environment=staging` | Test staging without editing `values.yaml` |
| `helm template first-chart . --set environment=production` | Test production without editing `values.yaml` |

## Conclusion

Helm templates reduce duplicated Kubernetes configuration. Combining `values.yaml` with `if`, `else`, and `end` generates staging and production ConfigMaps from a single reusable template.
