# Next Steps with Helm

## Course Summary

Helm is a **package manager for Kubernetes** that simplifies installing, configuring, upgrading, and removing applications. It helps manage the application lifecycle for both applications you build and software distributed by other organizations.

## Key Concepts Learned

### 1. Helm Package Management

- Helm packages Kubernetes resources into reusable **charts**.
- A deployed instance of a chart is called a **release**.
- Helm helps manage application installation, upgrades, rollbacks, and uninstallation.
- It is useful for deploying and maintaining production applications and microservices.

### 2. Finding and Managing Charts with Artifact Hub

- **Artifact Hub** helps you discover published Helm charts.
- Review a chart's publisher, documentation, version, dependencies, and security information before installing it.
- Use Helm commands to install, inspect, upgrade, and remove releases.

```bash
helm search hub cert-manager
helm install my-release <chart-reference>
helm list
helm upgrade my-release <chart-reference>
helm uninstall my-release
```

Replace `<chart-reference>` with a valid chart reference or local chart path.

### 3. Creating Your Own Helm Charts

Helm lets you package your own Kubernetes applications into charts.

```bash
helm create my-application
```

A typical chart contains:

```text
my-application/
├── Chart.yaml       # Chart metadata
├── values.yaml      # Default configuration values
├── charts/          # Optional dependent charts
└── templates/       # Kubernetes manifest templates
```

### 4. Dynamic Configuration with Helm Templates

- Templates allow the same chart to be reused across environments.
- Values in `values.yaml` can be referenced in templates with Helm's Go-based templating language.
- Configuration can be overridden using additional values files or `--set`.

Example template expression:

```yaml
replicas: {{ .Values.replicaCount }}
```

Preview rendered Kubernetes manifests before deployment:

```bash
helm template my-release ./my-application
```

## Recommended Next Steps

1. **Follow Helm development:** Visit the official Helm GitHub organization to learn about releases and project updates.
2. **Study Helm documentation:** Explore advanced features and best practices.
3. **Learn Kubernetes RBAC:** Understand how service accounts, roles, and role bindings affect Helm deployments and permissions.
4. **Test your charts:** Use `helm lint`, `helm template`, and `helm test` (when chart tests are defined).
5. **Practice a full release lifecycle:** Create a chart, install it, change values, upgrade the release, inspect its history, and uninstall it.
6. **Explore the broader Kubernetes ecosystem:** Evaluate related deployment, security, monitoring, and GitOps tools.

## Useful Helm Commands

| Command | Purpose |
|---|---|
| `helm create demo` | Scaffold a new chart |
| `helm lint ./demo` | Check a chart for common problems |
| `helm template demo ./demo` | Render manifests locally |
| `helm install demo ./demo` | Install a chart as a release |
| `helm list` | List releases in the current namespace |
| `helm upgrade demo ./demo` | Upgrade an existing release |
| `helm history demo` | Show release revision history |
| `helm rollback demo 1` | Roll back to revision 1, if available |
| `helm test demo` | Run tests defined in the chart, if any |
| `helm uninstall demo` | Remove a release |
