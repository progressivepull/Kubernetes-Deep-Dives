# 2.12 Configuring Azure access with a service principal

How to create and configure **Azure CLI access using a Service Principal** based on the transcript provided.

# **🤖 Why Use a Service Principal?**

Unlike the interactive browser login, a Service Principal acts as an automated service account. It is specifically designed for **CI/CD pipelines and automated scripts** where human browser interaction is impossible.

## **🛠️ Step 1: Create the Service Principal**

You must first be logged in via the interactive method (az login) to have the permissions required to create a service principal.

1.  **Find Your Subscription ID:** Run the following command to display your current account details, then copy the value under "id":

```bash

az account show

```

2.  **Generate the Service Principal:** Run the Role-Based Access Control (rbac) creation command, defining its access level and target scope:

```bash

az ad sp create-for-rbac --role owner --scopes /subscriptions/YOUR_SUBSCRIPTION_ID

```

*Note: The owner role used here is highly permissive; using a more restricted role is recommended for production environments.*

3.  **Save the Output:** The command will output a JSON object containing critical credentials. **Copy and secure these values immediately**:

    - appId (Acts as the username)

    - password (Acts as the secret key)

    - tenant (The directory ID)

## **🔐 Step 2: Log In Using the Service Principal**

Once the credentials are created, you can authenticate headlessly from any terminal or automation runner.

1.  Execute the login command by mapping the parameters to your saved JSON values:

```bash

az login --service-principal --username "YOUR_APP_ID" --password "YOUR_PASSWORD" --tenant "YOUR_TENANT_ID"

```

2.  **Verify the Connection:** Upon success, the CLI returns a confirmation JSON array. Look for the "user" block: the "type" field will explicitly state **"servicePrincipal"**, confirming you are no longer using personal user credentials.
