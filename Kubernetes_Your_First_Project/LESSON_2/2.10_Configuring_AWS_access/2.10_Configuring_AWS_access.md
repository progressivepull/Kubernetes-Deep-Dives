# 2.10 Configuring AWS access

How to configure **AWS CLI access** and implement secure, short-lived permissions using IAM roles based on the transcript provided.

# **👤 Step 1: Create a Zero-Permission IAM User**

For security, the user is initially created with no permissions so that if the persistent credentials leak, your account remains safe.

1.  Navigate to the AWS Console (console.aws.amazon.com) and open **IAM**.

2.  Go to **Users** -> **Create user**, and name the user (e.g., Carlos). Proceed through the steps without adding any permissions or groups.

3.  Click on the newly created user, go to the **Security credentials** tab, and select **Create access key**.

4.  Choose **Command Line Interface (CLI)**, accept the prompts, and download the provided **CSV file** containing your Access Key ID and Secret Access Key.

# **🛡️ Step 2: Create an IAM Role & Trust Relationship**

You will grant the actual operational permissions to an IAM role that your user can temporarily assume.

1.  In the IAM dashboard, click **Roles** -> **Create role** and choose **AWS account**.

2.  Check **Require external ID** (acts like a session password, e.g., supersecret).

3.  Attach your desired permissions (e.g., AdministratorAccess) and name the role (e.g., carlos-role).

4.  Open the created role, go to the **Trust relationships** tab, click **Edit trust policy**, and change the Principal from "root" to your specific user (e.g., "user/carlos"). Copy the role's **ARN** for later.

# **⚙️ Step 3: Configure the Persistent Base Credentials**

Link your local terminal to the zero-permission user.

1.  Open your terminal and run:

```bash

aws configure

```

2. Paste the **AWS Access Key ID** and **Secret Access Key** from your downloaded CSV file.

3. Enter your default region (e.g., `us-east-2`) and leave the output format as `none`.

4. **(Optional Test)** Running `aws ec2 describe-instances` here will fail with an Access Denied error, confirming the base user has no permissions.

# 🔑 **Step 4: Assume the Role & Set Session Variables**

Generate temporary credentials that automatically expire over time.

1. Run the Security Token Service (`sts`) command to assume the high-permission role:

```bash

aws sts assume-role --role-arn "YOUR_COPIED_ROLE_ARN" --external-id "supersecret" --role-session-name "my-session"

```

2.  This command outputs a large JSON blob containing an AccessKeyId, SecretAccessKey, and SessionToken.

3.  Export these short-lived keys as environment variables in your terminal to begin running privileged commands:

    - **macOS Terminal:**

```bash

export AWS_SESSION_TOKEN="copied_session_token"

export AWS_ACCESS_KEY_ID="copied_access_key_id"

export AWS_SECRET_ACCESS_KEY="copied_secret_access_key"

```
