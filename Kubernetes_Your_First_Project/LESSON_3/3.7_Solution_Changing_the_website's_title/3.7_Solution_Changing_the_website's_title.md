# 3.7 Solution Changing the website's title

## **🔍** Step 1: Factual Verification (Optional Checks)

Before executing the build, the instructor verifies the contents of the challenge project (03_06b) inside the editor to guarantee correctness:

- **Web Title:** Opening website/index.htm confirms the \<title\> tag matches the requested string: *“Tours, Adventure, Travel, Explore California”*.

- **Nginx Configuration:** Running a search for root inside nginx.conf confirms the server block accurately points to the new path requested by cybersecurity: /usr/share/nginx/website.

- **Container Blueprint:** Checking the Containerfile verifies the internal instructions correctly map the local assets to the new destination: COPY website /usr/share/nginx/website.

## **🏗️** Step 2: Building the Challenge Image

Once the assets are verified, the container image is compiled and tagged using the Podman engine:

```bash

podman build -t explorecalifornia.com-new .

```

*Note: The instructor mentions that the image tag itself can technically be named anything, but naming it identically to the target container name (explorecalifornia.com-new) simplifies local asset tracking.*

**🚀** Step 3: Running and Validating the Container

To finish the challenge, the container is launched with clean-up mechanisms and port routing:

``bash

podman run --rm --name explorecalifornia.com-new -p 5000:80 explorecalifornia.com-new

```

- **Port Mapping Strategy:** Follows the **Outside : Inside** paradigm (5000:80), mapping port 5000 on the local host machine to port 80 inside the running Nginx container.

- **Validation Success:** The terminal output indicates Nginx is ready. Opening a browser to localhost:5000 loads the web application smoothly and successfully displays the updated text string in the browser tab's title bar, marking the challenge complete.
