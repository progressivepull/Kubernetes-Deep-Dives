**📄** Dockerfile vs. Containerfile

When exploring the directory, three project-specific files appear: website, nginx.conf, and Containerfile.

- **Containerfile** is the default filename used by the **Podman** container engine.

- **Dockerfile** is the default filename native to the **Docker CLI**.

- Both file types are functionally identical and completely interchangeable across either container runtime.

**⚙️** Core Containerfile Commands Explained

The instructor opens the file in Vim to unpack the layer-by-layer anatomy of the container blueprint:

Containerfile

```
FROM nginx:alpine
LABEL maintainer="Your Name <your@email.address>
COPY website /website
COPY nginx.conf /etc/nginx/nginx.conf
EXPOSE 80
```

- FROM nginx:alpine – Specifies the **base image**. Container images are stacked sequentially on top of pre-existing environments. The FROM instruction must always occupy the absolute first line of the file, or the build engine will error out.

- LABEL maintainer=Your Name... – Injects metadata key-value pairs (without spaces in the key) into the image context for documentation or tracking purposes.

- COPY nginx.conf  COPY website – Pulls files and code folders out of the local build system's **context** and bakes them securely into the internal container image filesystem.

- EXPOSE – Acts as an internal documentation layer signaling to users which networking port the underlying web server or application intends to listen on inside the runtime environment.
