# 3.1 Lets containerize Explore California

**📦** Containerization in Kubernetes

- **The Baseline Requirement:** Applications running in a Kubernetes cluster almost always execute inside containers built from static **container images**.

- **Explore California's Status:** Because the Explore California application already utilizes Docker containers in its production environment, the foundational infrastructure is already aligned for cloud-native deployment.

**🛠️** The Containerization Roadmap

This section serves as a practical refresher to prepare the application for a Kubernetes environment by executing three primary steps:

1.  **Review the Blueprint:** Examine the application's container configuration file, commonly referred to interchangeably as a **Dockerfile** or a **Containerfile**.

2.  **Build the Image:** Construct a reusable container image using modern building engines, specifically **Podman** and **Docker’s BuildKit**.

3.  **Run and Test:** Instantiate a running container from the compiled image locally.

**🎯** Strategic Objective

This entire local containerization process acts as a critical **pre-flight test**. Successfully building and running the container locally ensures that the Explore California application is stable and fully capable of operating within a managed Kubernetes architecture.
