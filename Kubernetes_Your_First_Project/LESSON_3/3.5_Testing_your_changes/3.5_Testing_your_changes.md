# 3.5 Testing your changes

# The Execution Command Breakdown

To instantiate and launch the local application container, use the following terminal command (works interchangeably with podman or docker):

bash

podman run --rm --name explorecalifornia.com -p 5000:80 explorecalifornia.com

- **run**: Performs two distinct operations at once: it **creates** the isolated container environment from the image and **starts** the underlying application process.

- **--name explorecalifornia.com**: Explicitly names the running container for easy management. If omitted, the engine automatically assigns a random name and a long hexadecimal ID.

- **--rm**: Automatically **deletes the container's file system** once the application terminates. This keeps your local engine clean by preventing dead container accumulation.

- **explorecalifornia.com (at the end)**: Specifies the compiled container image target to boot up.

# **🔌** Understanding Port Mapping (-p)

The command uses -p 5000:80 to bridge the container's isolated network environment with your local machine. A helpful memory aid for the syntax is **Outside : Inside**.

- **Outside (5000)**: The port exposed to your physical host machine.

- **Inside (80)**: The internal target port the application listens to within the container.

- *Note:* The internal target (port 80) was determined by checking the EXPOSE instruction inside the application's original configuration file blueprint.

File Name: Containerfile

```bash

FROM nginx:alpine
LABEL maintainer="Your Name <your@email.address>"
COPY website /website
COPY nginx.conf /etc/nginx/nginx.conf
EXPOSE 80

```

# **🎯 Verification and Success Criteria**

- **Engine Logs:** Upon execution, Nginx (the container's base image software layer) prints out initialization tracking data terminating in a notice stating it is ready to accept connections.

- **Local Browser Check:** Navigating a web browser to localhost:5000 successfully pulls up the live **Explore California** application homepage.

- **Next Horizon:** This successful local execution proves the application configuration is stable and prepared for final transition into an orchestrated Kubernetes environment.
