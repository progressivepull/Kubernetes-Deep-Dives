# 5.11 Chapter Quiz

# Question 1

How do Ingress objects within Kubernetes expose your application out to the Internet?

- They do not expose applications within Kubernetes to the Internet by default. You will need to edit /etc/hosts before you can use Ingress objects.

- They serve your application through Layer 7 reverse proxies.

**Correct**

Ingress use ingress controllers (reverse web proxies) to route traffic to your application by URL.

- They serve your application using Layer 4 load balancing.

- They serve your application by adding an "allow all" Network Policy in its Kubernetes namespace.

# Question 2

Which of these types of Services will expose your application out to the Internet with a supported cloud provider?

- ClusterIP

- NodePort

- LoadBalancer

**Correct**

ClusterIP services will be given an IP that is only reachable within the cluster. LoadBalancer services, however, work with your cloud provider to expose your application out to the Internet.

# Question 4

Which of these services does cert-manager help simplify?

- enabling SSL for Services served by Ingresses

- creating certificates from certificate authorities automatically

**Correct**

cert-manager works with certificate authorities to automatically retrieve certificates for applications in a Kubernetes cluster.

- running root certificate authorities in Kubernetes

- enabling SSL for Deployments served by Ingresses

# Question 5

You are trying to replicate a production incident in a local Kind cluster. The application affected by this incident uses an Ingress to expose itself out to the Internet. You want to verify that you can access the application through the Ingress. Most users use the application through a web browser. Which of these options best summarizes how to accomplish this?

- Use kubectl port-forward \<website\> to verify connectivity locally. Visit \<website\> in a browser

- Add 127.0.0.1 to /etc/hosts. Use kubectl port-forward to verify connectivity locally.

**Incorrect**

- Use kubectl port-forward to verify connectivity locally.

**Incorrect**

- Add 127.0.0.1 to /etc/hosts. Visit in a browser.

**Correct**

While you can use port-forward to troubleshoot the application, modifying your system's /etc/host file will test whether your ingress responds to traffic by hostname.

# Question 10

You are a platform engineer that is building a container platform for your financial services company. To maintain compliance with your country's financial services regulations, you must ensure that every web application that runs in your container platform can only be accessed with HTTPS. You want to enable this capability for every web application in your platform regardless of whether the application supports HTTPS or not. Your company has its own certificate authority. Which of these options will help you most easily meet this requirement?

- Ensure that every Ingress in your cluster has the ingress.kubernetes.io/enable-ssl: true annotation set.

- Install cert-manager. Create an Issuer that issues certificates from your company's root certificate authority. Ensure that every Ingress in your cluster has a cert-manager.io/issuer annotation pointing to your Issuer.

**Correct**

cert-manager will automatically request a certificate for your application once you create an Issuer and annotate your Ingress to select it.

- Ensure that every Service in your cluster has the ingress.kubernetes.io/enable-ssl: true annotation set.

- Install cert-manager. Create an Issuer that issues certificates from your company's root certificate. Ensure that every Service in your cluster has a cert-manager.io/issuer annotation pointing to your Issuer.

# Question 11

Which of these commands will create a cluster within Kind named my-cluster?

- kind create --cluster my-cluster

- kind create cluster --name my-cluster

**Correct**

You need to provide --name in order to name your Kind Kubernetes cluster.

- kind cluster create --name my-cluster

- kind create cluster my-cluster
