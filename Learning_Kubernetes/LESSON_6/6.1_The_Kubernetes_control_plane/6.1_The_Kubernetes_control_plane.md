# 6.1 The Kubernetes control plane

**Understanding the Kubernetes Control Plane**

A Kubernetes **cluster** consists of a control plane and at least one worker node.

The control plane is responsible for managing the cluster and ensuring that Kubernetes resources, such as pods and deployments, are created, updated, and deleted correctly.

Think of Kubernetes like an airport:

- **Control plane:** The air traffic control tower that manages operations.

- **Worker nodes:** The airplanes and runways where the actual work happens.

**1. Kubernetes Control Plane Components**

There are five main components of the Kubernetes control plane.

**1. Kube API Server**

Most important component

- Exposes the Kubernetes API.

- Handles requests from users and other cluster components.

- Allows tools like kubectl and kubeadm to communicate with Kubernetes.

- Uses a REST interface and HTTP requests.

- Every Kubernetes object has an API endpoint.

Useful commands:

bash

kubectl api-resources

Lists available Kubernetes API resources and their API versions.

bash

kubectl -n kube-system get pods

Lists pods running in the kube-system namespace.

Look for a pod whose name starts with kube-apiserver.

**2. etcd**

- An open-source, highly available key-value store.

- Stores information about the state of the Kubernetes cluster.

- Keeps track of cluster data and configuration.

- Only the Kube API Server communicates directly with etcd.

To inspect etcd:

bash

kubectl -n kube-system get pods

Find the etcd pod, then view its logs:

bash

kubectl logs \<etcd-pod-name\> -n kube-system

**3. Kube Scheduler**

- Identifies newly created pods that haven't been assigned to a worker node.

- Selects the appropriate worker node for each pod.

- Helps determine where workloads should run.

You can inspect it using:

bash

kubectl -n kube-system get pods

You can also use kubectl describe or kubectl logs to investigate the scheduler.

**4. Kube Controller Manager**

- Continuously monitors the state of the Kubernetes cluster.

- Checks that resources are operating as expected.

- Helps maintain the desired state of the cluster.

- Manages different controllers responsible for keeping Kubernetes resources healthy.

For example, controllers detect when a pod is missing and work to restore the desired number of replicas.

**5. Cloud Controller Manager**

- Connects Kubernetes to cloud provider APIs.

- Allows Kubernetes to use cloud resources.

- Supports cloud providers such as:

  - AWS

  - Google Cloud Platform (GCP)

  - Microsoft Azure

It helps Kubernetes integrate with external cloud infrastructure.

**2. Control Plane Components at a Glance**

| **Component**            | **Main responsibility**                |
|--------------------------|----------------------------------------|
| Kube API Server          | Handles Kubernetes API requests        |
| etcd                     | Stores cluster state and data          |
| Kube Scheduler           | Assigns pods to worker nodes           |
| Controller Manager       | Monitors and maintains cluster state   |
| Cloud Controller Manager | Connects Kubernetes to cloud providers |

**3. Important Kubernetes Commands**

| **Command** | **Purpose** |
|----|----|
| kubectl api-resources | Lists Kubernetes API resources |
| kubectl -n kube-system get pods | Lists control plane pods |
| kubectl describe pod \<pod-name\> -n kube-system | Displays pod details |
| kubectl logs \<pod-name\> -n kube-system | Displays component logs |

**4. Important Note: Managed Kubernetes Services**

If you're using managed Kubernetes services such as:

- AWS EKS

- Google GKE

- Azure AKS

You might not be able to view the control plane nodes using kubectl.

Why?

Because the cloud provider manages and maintains the control plane components for you.

**Key Takeaways**

- A Kubernetes cluster consists of a control plane and worker nodes.

- The control plane manages and coordinates the cluster.

- The API Server is the main communication gateway.

- etcd stores the cluster's state.

- The Scheduler assigns pods to worker nodes.

- The Controller Manager continuously monitors cluster resources.

- The Cloud Controller Manager connects Kubernetes to cloud infrastructure.

**Remember this simple way to understand the five components:**

1.  API Server = Communication

2.  etcd = Storage

3.  Scheduler = Placement

4.  Controller Manager = Monitoring and maintaining desired state

5.  Cloud Controller Manager = Cloud integration

**Main lesson:** The Kubernetes control plane is the brain of the cluster. It coordinates resources, maintains the desired state, and automates cluster management.
