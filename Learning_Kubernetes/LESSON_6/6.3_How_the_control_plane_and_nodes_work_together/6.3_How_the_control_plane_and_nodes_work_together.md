# 6.3 How the control plane and nodes work together

**How the Kubernetes Control Plane and Worker Nodes Work Together**

In this lesson, we learn how the Kubernetes control plane and worker nodes communicate to create and run a pod.

The instructor uses a **time sequence diagram** to explain the order of events from the moment a user runs a kubectl command until a pod is successfully running.

**1. The Three Main Parts**

The process involves three main participants:

1.  **You (the user):** Run Kubernetes commands using kubectl.

2.  **Control Plane:** Manages the cluster and decides where pods should run.

3.  **Worker Node:** Receives pod instructions and runs containers.

**2. Step-by-Step: How Kubernetes Creates a Pod**

**Step 1: Apply the Deployment**

You run:

bash

kubectl apply -f deployment.yaml

- kubectl communicates with the Kubernetes cluster.

- Your kubeconfig file provides the connection and authentication information.

- The request is sent to the Kube API Server.

**Step 2: API Server Saves the Deployment**

The Kube API Server:

- Receives the deployment configuration.

- Validates the request.

- Stores the desired cluster state in etcd.

**Remember:** The API Server is the main communication gateway to Kubernetes.

**Step 3: Controller Manager Detects Changes**

The Kube Controller Manager continuously monitors the cluster.

- It checks whether the actual state matches the desired state.

- It detects changes, such as a newly created Deployment.

- It works with controllers to ensure the required resources are created.

**Step 4: Scheduler Selects a Worker Node**

The Kube Scheduler:

- Checks for newly created pods that haven't been assigned to a node.

- Evaluates available worker nodes.

- Selects an appropriate node for the pod.

- Sends the scheduling decision to the API Server.

The API Server records the updated state in etcd.

**Step 5: Kubelet Receives the Pod Instructions**

On the selected worker node:

- The Kubelet communicates with the API Server.

- It checks whether any new pods have been assigned to its node.

- The API Server provides the pod specification.

**Step 6: Container Runtime Creates the Container**

The Kubelet instructs the container runtime to:

- Pull the required container image if necessary.

- Create the container.

- Start the container inside the pod.

**Step 7: Kubelet Reports Pod Status**

After the pod starts:

- The Kubelet checks the pod's status.

- It reports the pod status to the API Server.

- The API Server updates the cluster state in etcd.

The pod can now be reported as running and healthy, provided its startup and health checks succeed.

**3. Kubernetes Pod Creation Flow**

1.  **User runs kubectl**

kubectl apply -f deployment.yaml

2.  **Kube API Server**

Receives and validates the deployment request.

3.  **etcd**

Stores the desired cluster state.

4.  **Controller Manager**

Detects changes and ensures the desired resources are created.

5.  **Kube Scheduler**

Selects a worker node for the new pod.

6.  **Kubelet**

Receives the pod specification on the selected node.

7.  **Container Runtime**

Pulls the image if needed and starts the container.

8.  **Kubelet reports status**

Sends pod status back to the API Server.

9.  **etcd updated**

The API Server stores the latest cluster state.

Pod created

**4. Role of Each Component**

| **Component**      | **Responsibility**                |
|--------------------|-----------------------------------|
| kubectl            | Sends commands to Kubernetes      |
| Kube API Server    | Processes Kubernetes API requests |
| etcd               | Stores cluster state              |
| Controller Manager | Maintains desired state           |
| Scheduler          | Selects a worker node             |
| Kubelet            | Manages pods on worker nodes      |
| Container Runtime  | Creates and runs containers       |

**5. Important Concepts to Remember**

- **Desired state:** What you want Kubernetes to create and maintain.

- **Actual state:** What is currently happening in the cluster.

- **Reconciliation:** Kubernetes continuously works to make actual state match desired state.

- **Scheduling:** Selecting the worker node where a pod should run.

- **etcd:** Stores the cluster's state and configuration.

- **Kubelet:** Makes sure assigned pods are running on its worker node.

**Key Takeaways**

1.  You use kubectl to submit deployment instructions.

2.  The API Server receives and processes the request.

3.  etcd stores the cluster state.

4.  The Scheduler selects a worker node.

5.  The Kubelet receives the pod specification.

6.  The Container Runtime starts the container.

7.  The Kubelet reports the pod's status back to the API Server.

**Main lesson:** The control plane makes decisions and manages the cluster, while worker nodes execute the workloads. They communicate through the Kubernetes API Server to create, monitor, and maintain pods.

**Easy way to remember:**

- Control Plane = Decides what should happen.

- Scheduler = Decides where it happens.

- Kubelet = Makes it happen.

- Container Runtime = Runs the application.

- etcd = Remembers the cluster state.
