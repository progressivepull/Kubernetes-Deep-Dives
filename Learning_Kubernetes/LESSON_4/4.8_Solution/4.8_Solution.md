# 4.8 Solution

**Chapter 3 Challenge Solution – Create a Quote Service Deployment**

In this video, the instructor demonstrates how to complete the Kubernetes challenge by creating a Deployment named quote-service and testing it using BusyBox.

**1. Create the YAML file**

Create a new file called quote.yaml:

bash

touch quote.yaml

Open the file in your text editor and use an existing Deployment YAML as a template.

**2. Configure the Deployment**

Update the YAML file with the challenge requirements:

yaml

apiVersion: apps/v1

kind: Deployment

metadata:

name: quote-service

namespace: development

labels:

app: quote-service

spec:

replicas: 2

selector:

matchLabels:

app: quote-service

template:

metadata:

labels:

app: quote-service

spec:

containers:

\- name: quote-container

image: datawire/quote:0.5.0

ports:

\- containerPort: 8080

Important changes:

- Deployment name: quote-service

- App label: quote-service

- Namespace: development

- Container name: quote-container

- Replicas: 2

- Image: datawire/quote:0.5.0

- Container port: 8080

- Removed unnecessary environment variables.

**3. Deploy the application**

Run:

bash

kubectl apply -f quote.yaml

Expected result: The quote-service deployment is created.

**4. Verify the pods**

bash

kubectl get pods -n development

You should see **two quote-service pods running**.

**5. Test the application using BusyBox**

The instructor uses BusyBox to send an HTTP request to the quote-service application from inside the Kubernetes cluster.

**Step 1: Enter the BusyBox pod**

bash

kubectl exec -it \<busybox-pod-name\> -- /bin/sh

**Step 2: Get the quote-service pod IP address**

In another terminal, run:

bash

kubectl get pods -n development -o wide

Copy the IP address of one quote-service pod.

**Step 3: Test the connection**

Try the default port 80:

bash

wget \<pod-ip-address\>

Connection refused

This happens because the application listens on port 8080, not port 80.

Try again using the correct port:

bash

wget \<pod-ip-address\>:8080

**Step 4: Fix the existing index.html file**

If you receive an error saying index.html already exists, delete the old file:

bash

rm index.html

Run the request again:

bash

wget \<pod-ip-address\>:8080

Connection successful

**Step 5: View the response**

bash

cat index.html

The output contains a JSON object with:

- Server name

- Random quote

- Timestamp

This confirms that the quote-service application is responding.

**6. Important Commands to Remember**

| **Command**                             | **Purpose**                   |
|-----------------------------------------|-------------------------------|
| touch quote.yaml                        | Create YAML file              |
| kubectl apply -f quote.yaml             | Deploy application            |
| kubectl get pods -n development         | Check pods                    |
| kubectl exec -it \<pod\> -- /bin/sh     | Enter BusyBox                 |
| kubectl get pods -n development -o wide | Find pod IP                   |
| wget \<pod-ip\>:8080                    | Test application              |
| rm index.html                           | Remove existing response file |
| cat index.html                          | View application response     |

**Key Takeaways**

1.  Kubernetes Deployments are configured using YAML manifests.

2.  Labels must match the Deployment selector.

3.  Replicas determine how many pod instances Kubernetes maintains.

4.  The container port must match the port used by the application.

5.  BusyBox allows you to test connectivity between pods internally.

6.  A connection refused error can indicate that you're using the wrong port.

7.  A successful HTTP response confirms that the application is responding.

**Remember:** Chapter 3 teaches you how to create deployments, inspect pods, troubleshoot problems, view application logs, and test application connectivity using BusyBox.
