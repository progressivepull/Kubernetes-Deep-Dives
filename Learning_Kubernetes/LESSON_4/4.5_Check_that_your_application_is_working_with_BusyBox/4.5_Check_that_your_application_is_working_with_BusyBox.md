# 4.5 Check that your application is working with BusyBox

**Checking Your Application with BusyBox in Kubernetes**

BusyBox is a lightweight Linux utility that includes common Unix tools such as wget, awk, and date. In Kubernetes, it can be used to troubleshoot and verify that an application is working correctly, even if the application is not exposed to the internet.

**Steps to Test Your Application**

**1. Deploy a BusyBox pod**

Use a YAML deployment file to create one BusyBox replica in the default namespace.

```bash
kubectl apply -f busybox.yaml
```

**2. Verify that BusyBox is running**

```bash
kubectl get pods
```

**3. Find your application's pod IP address**

```bash
kubectl get pods -n development -o wide
```

The -o wide option displays additional information, including the pod's IP address.

**4. Enter the BusyBox container**

```bash
kubectl exec -it <busybox-pod-name> -- /bin/sh
```
- **kubectl exec:** Executes a command inside a container.
- **-it:** Opens an interactive terminal.
- **<busybox-pod-name>:** Specifies the BusyBox pod.
- **/bin/sh:** Opens the shell inside the container.

**5. Check that wget is installed**

```bash
wget
```

BusyBox displays usage information if wget is available.

**6. Test your application using wget**

First, try connecting using the default HTTP port (80):

```bash
wget <pod-ip-address>
```

If the connection is refused, check which port your application uses.

In this example, the application listens on port 3000, not port 80.

Run:

```bash
wget <pod-ip-address>:3000
```

If successful, wget downloads the response into a file called index.html.

**7. View the application response**

```bash
cat index.html
```

The output displays the JSON response containing environment variables configured in the application's deployment YAML.

**8. Exit the BusyBox container**

```bash
exit
```

**Important Commands to Remember**

| **Command**                             | **Purpose**                   |
|-----------------------------------------|-------------------------------|
| kubectl apply -f busybox.yaml           | Deploy BusyBox                |
| kubectl get pods                        | List pods                     |
| kubectl get pods -n development -o wide | Get pod IP addresses          |
| kubectl exec -it \<pod\> -- /bin/sh     | Enter a container             |
| wget \<pod-ip\>:3000                    | Test application connectivity |
| cat index.html                          | View downloaded response      |
| exit                                    | Leave the container           |

**Key Takeaways**

- **BusyBox** is useful for **Kubernetes debugging and troubleshooting**.
- **kubectl** exec lets you **execute commands** inside a running container.
- **wget** can test **communication** between pods.
- **Pod IP addresse**s can be found using **kubectl get pods -o wide**.
- Always check the application's configured port when testing connectivity.
- You can verify an application internally without exposing it to the internet.

**Remember:** BusyBox acts as a temporary testing environment that lets you verify whether your application is reachable and responding correctly from inside your Kubernetes cluster.
