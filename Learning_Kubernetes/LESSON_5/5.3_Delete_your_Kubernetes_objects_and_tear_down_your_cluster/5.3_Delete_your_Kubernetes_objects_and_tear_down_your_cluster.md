# 5.3 Delete your Kubernetes objects and tear down your cluster

**Delete Your Kubernetes Objects and Tear Down Your Cluster**

In this lesson, we learn how to clean up Kubernetes resources and completely remove a Minikube cluster when we're finished using it.

Minikube uses computer resources such as CPU, memory, and storage, so it's important to shut it down when it's no longer needed.

**1. Delete Kubernetes Resources**

Kubernetes objects can be deleted using the YAML files that created them.

The command format is:

bash

kubectl delete -f \<filename\>.yaml

The instructor deletes the following resources one by one:

bash

kubectl delete -f busybox.yaml

kubectl delete -f deployment.yaml

kubectl delete -f quote.yaml

kubectl delete -f service.yaml

kubectl delete -f namespace.yaml

These commands delete the Kubernetes objects defined in each YAML file.

**2. Important: Delete the Namespace Last**

The namespace should generally be deleted after the other resources.

Why?

- A namespace contains Kubernetes resources such as pods, deployments, and services.

- Deleting a namespace automatically deletes the resources inside it.

- Deleting it last allows you to clean up individual resources first.

**Note:** You can delete the namespace first if you want Kubernetes to remove everything inside it automatically.

**3. Delete the Minikube Cluster**

After deleting the Kubernetes resources, remove the entire Minikube cluster.

Run:

bash

minikube delete

This removes the local Minikube cluster and its associated resources.

**4. Important Commands to Remember**

| **Command**                       | **Purpose**                       |
|-----------------------------------|-----------------------------------|
| kubectl delete -f busybox.yaml    | Delete BusyBox resources          |
| kubectl delete -f deployment.yaml | Delete application deployment     |
| kubectl delete -f quote.yaml      | Delete quote-service deployment   |
| kubectl delete -f service.yaml    | Delete Kubernetes Service         |
| kubectl delete -f namespace.yaml  | Delete namespace and its contents |
| minikube delete                   | Delete the Minikube cluster       |

**5. Recommended Cleanup Order**

1.  **Delete BusyBox**

Remove the temporary testing pod.

2.  **Delete Deployments**

Remove application deployments and their managed pods.

3.  **Delete Services**

Remove services exposing your applications.

4.  **Delete Namespace**

Remove the namespace and any remaining resources inside it.

5.  **Delete Minikube Cluster**

Run minikube delete to remove the local cluster.

**Key Takeaways**

- Always clean up Kubernetes resources when they're no longer needed.

- Use kubectl delete -f to delete resources using YAML manifests.

- Deleting a namespace also deletes the resources inside it.

- Delete the namespace last when cleaning up resources individually.

- Use minikube delete to completely remove your local cluster.

- Cleaning up prevents unnecessary consumption of computer resources.

**Main lesson:** Kubernetes cleanup is just as important as deployment. Knowing how to delete resources and tear down a cluster helps you manage your development environment efficiently.
