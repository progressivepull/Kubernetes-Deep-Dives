# 5.1 Expose your application to the internet with a LoadBalancer

**Expose Your Application to the Internet with a LoadBalancer**

In this lesson, we learn how to make a Kubernetes application accessible from outside the cluster using a **Kubernetes Service of type LoadBalancer**.

Previously, we accessed our application using BusyBox from inside the cluster. Now we'll expose it so users can access it through a browser.

**1. What Is a Kubernetes Service?**

A Kubernetes Service provides a stable way to access application pods.

Pods can be created, deleted, or replaced, which means their IP addresses can change. A Service provides a consistent endpoint for accessing them.

A LoadBalancer Service:

- Exposes an application outside the Kubernetes cluster.

- Provides an external IP address.

- Distributes incoming traffic to matching pods.

- Provides a stable access point even when pod IP addresses change.

**2. Create a Service YAML File**

Create a file called service.yaml.

Example configuration:

yaml

apiVersion: v1

kind: Service

metadata:

name: demo-service

namespace: development

spec:

selector:

app: pod-info

ports:

\- port: 80

targetPort: 3000

type: LoadBalancer

**Understanding the Configuration**

| **Setting**             | **Purpose**                             |
|-------------------------|-----------------------------------------|
| apiVersion: v1          | Specifies the Kubernetes API version    |
| kind: Service           | Creates a Service resource              |
| name: demo-service      | Names the Service                       |
| namespace: development  | Deploys it in the development namespace |
| selector: app: pod-info | Identifies which pods receive traffic   |
| port: 80                | Port exposed by the Service             |
| targetPort: 3000        | Port used by the application container  |
| type: LoadBalancer      | Exposes the Service externally          |

Important

The Service selector must match the labels on your Deployment pods.

For example:

yaml

labels:

app: pod-info

If the labels don't match, the Service won't find the intended pods.

**3. Start Minikube Tunnel**

Before creating the Service, open a separate terminal and run:

bash

minikube tunnel

Minikube tunnel allows LoadBalancer Services to work in a local Minikube environment.

It may request your computer password to authorize the network configuration.

Keep this terminal running while testing the application.

**4. Create the Kubernetes Service**

In your other terminal, run:

bash

kubectl apply -f service.yaml

Expected result:

text

service/demo-service created

**5. Find the External IP Address**

Run:

bash

kubectl get services -n development

You'll see information similar to this:

| **Name**     | **Type**     | **Cluster IP** | **External IP** | **Port** |
|--------------|--------------|----------------|-----------------|----------|
| demo-service | LoadBalancer | Internal IP    | 127.0.0.1       | 80       |

There are two important IP addresses:

- **Cluster IP:** Used for communication inside the Kubernetes cluster.

- **External IP:** Used to access the application from outside the cluster.

**6. Access Your Application**

Copy the external IP address and open it in your browser:

text

http://127.0.0.1

If everything is configured correctly, you'll see the JSON response from the pod-info application.

**Important:** Minikube uses your local computer, so 127.0.0.1 is a localhost address, not a publicly accessible internet IP.

In cloud environments such as AWS, Azure, or Google Cloud, a LoadBalancer Service can receive a publicly accessible IP address, depending on the cloud configuration.

**7. Stop Minikube Tunnel**

When you're finished testing, return to the terminal running Minikube tunnel and press:

text

Ctrl + C

This stops the tunnel process.

**8. Important Kubernetes Service Types**

Kubernetes has three commonly used Service types:

| **Service Type** | **Purpose**                                            |
|------------------|--------------------------------------------------------|
| ClusterIP        | Exposes applications internally within the cluster     |
| NodePort         | Exposes applications through a port on each node       |
| LoadBalancer     | Exposes applications through an external load balancer |

**Key Takeaways**

- A Kubernetes Service provides stable access to pods.

- LoadBalancer exposes applications outside the cluster.

- Services use selectors to identify the correct pods.

- The Service selector must match the pod labels.

- port is the Service port, while targetPort is the application container port.

- Minikube requires minikube tunnel to simulate LoadBalancer functionality locally.

- Cloud providers can provision publicly accessible external IP addresses.

**Important Commands to Remember**

| **Command** | **Purpose** |
|----|----|
| minikube tunnel | Enables LoadBalancer access in Minikube |
| kubectl apply -f service.yaml | Creates the Service |
| kubectl get services -n development | Displays Service information |
| kubectl describe service demo-service -n development | Shows Service details |

**Remember these three concepts:**

1.  Deployment = Creates and manages pods.

2.  Service = Provides stable access to pods.

3.  LoadBalancer = Exposes your application externally.

**Main lesson:** A LoadBalancer Service allows users outside your Kubernetes cluster to access your application without needing to know the individual pod IP addresses.
