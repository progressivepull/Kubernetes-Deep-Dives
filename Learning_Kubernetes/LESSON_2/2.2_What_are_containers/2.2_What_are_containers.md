# 2.2 What are containers

**Summary: What Are Containers?**

**Containers** are lightweight, portable units that package an application’s code, dependencies, and configuration so it can run consistently across different environments.

**Key Benefits of Containers**

- **Portability:** Run on Linux, Windows, or macOS with a compatible container engine.

- **Efficiency:** Use fewer CPU and memory resources than traditional virtual machines in many cases.

- **Speed:** Start and stop in seconds because the application and its dependencies are packaged together.

- **Scalability:** Easily create or remove replicas to handle changing workloads.

- **Cost savings:** Run more application instances on fewer servers.

**Important Terms**

- **Container image:** A package containing the executable application and everything needed to create a container.

- **Container registry:** A storage service for container images, such as Docker Hub, Quay, or Google Container Registry.

- **Container runtime:** Software that creates and runs containers, such as containerd or other compatible runtimes.

- **Kubernetes:** A container orchestration platform that manages container deployment, scaling, and operation.

- **Docker:** A popular container technology used to build and manage container images and containers.

**How Containers Work with Kubernetes**

1.  Kubernetes pulls a container image from a registry.

2.  You specify how many replicas of the application should run.

3.  Kubernetes uses a container runtime to start the containers.

4.  Kubernetes manages the application and helps scale the number of replicas as needed.

**In simple terms:** Think of a container as a portable package containing everything an application needs to run. Kubernetes acts like a manager that deploys, monitors, and scales those containers.
