# 3.6 Install minikube on macOS

**Summary: Install Minikube on macOS**

**1. What is Minikube?**

Minikube is a free, open-source tool that allows you to run a local Kubernetes cluster on your macOS computer.

It is primarily used for:

- Learning Kubernetes concepts.

- Practicing Kubernetes commands.

- Developing and testing containerized applications.

- Running Kubernetes without paying for cloud infrastructure.

Important: Minikube is intended primarily for learning and development, not production environments.

**2. Prerequisites**

Before installing Minikube on macOS, you need:

| **Requirement**     | **Description**                          |
|---------------------|------------------------------------------|
| macOS               | Apple operating system                   |
| Terminal            | Used to execute commands                 |
| Homebrew            | Package manager used to install Minikube |
| Container runtime   | Docker or Podman                         |
| Internet connection | Required to download Minikube            |
| Hardware resources  | Sufficient CPU, memory, and disk space   |

The instructor uses Docker as the container runtime.

**3. Install Minikube on macOS**

Step 1: Install Minikube using Homebrew

**<span class="mark">brew install minikube</span>**

Homebrew automatically downloads and installs Minikube.

Installation typically takes a few minutes.

Step 2: Verify the installation

<span class="mark">minikube version</span>

This displays the installed Minikube version.

**4. Start a Kubernetes Cluster**

Start a local Kubernetes cluster:

**<span class="mark">minikube start</span>**

To explicitly use Docker:

**<span class="mark">minikube start --driver=docker</span>**

Minikube creates and configures a Kubernetes cluster on your computer. This process may take several minutes.

**5. Verify the Kubernetes Cluster**

Once the cluster is running, check its nodes:

**<span class="mark">kubectl get nodes</span>**

This command displays the Kubernetes nodes and their status.

Example output:

NAME STATUS ROLES AGE VERSION

minikube Ready control-plane 2m v1.33.0

Explanation:

- NAME: Name of the Kubernetes node.

- STATUS: Indicates whether the node is ready.

- ROLES: Identifies the node's Kubernetes role.

- AGE: How long the node has existed.

- VERSION: Kubernetes version running on the node.

**6. Check for Minikube Updates**

Run:

**<span class="mark">minikube update-check</span>**

This compares your installed Minikube version with the latest stable version.

If the versions match, your installation is up to date.

**7. Stop and Delete the Cluster**

Stop the cluster:

**<span class="mark">minikube stop</span>**

This stops the local Kubernetes cluster without deleting its configuration.

Delete the cluster:

**<span class="mark">minikube delete</span>**

This removes the Minikube cluster and its associated cluster resources.

**8. Common Minikube Commands**

| **Command**                    | **Purpose**                           |
|--------------------------------|---------------------------------------|
| brew install minikube          | Install Minikube using Homebrew       |
| minikube version               | Display installed Minikube version    |
| minikube start                 | Create and start a Kubernetes cluster |
| minikube start --driver=docker | Start a cluster using Docker          |
| kubectl get nodes              | Display Kubernetes nodes              |
| minikube update-check          | Check for newer Minikube versions     |
| minikube status                | Check cluster status                  |
| minikube stop                  | Stop the cluster                      |
| minikube delete                | Delete the cluster                    |
| minikube dashboard             | Open the Kubernetes dashboard         |

**9. Minikube vs. Production Kubernetes**

| **Feature** | **Minikube** | **Production Kubernetes** |
|----|----|----|
| Primary purpose | Learning and testing | Running production applications |
| Infrastructure | Local computer | Cloud or data center |
| Cost | Free software; uses local resources | Infrastructure and operational costs |
| Scalability | Limited by local resources | Supports large-scale workloads |
| Security | Development-focused | Production security controls |
| Networking | Local networking | Advanced networking capabilities |

**10. Key Takeaways**

1.  Minikube runs Kubernetes locally on macOS.

2.  Homebrew simplifies the Minikube installation process.

3.  Docker or Podman provides the container environment.

4.  minikube start creates and starts a Kubernetes cluster.

5.  kubectl get nodes verifies that Kubernetes nodes are running.

6.  minikube update-check checks whether a newer version is available.

7.  minikube stop stops the cluster without deleting it.

8.  minikube delete removes the cluster.

**11. Exam Tips**

Remember these important commands:

- Install Minikube: brew install minikube

- Start cluster: minikube start

- Check Kubernetes nodes: kubectl get nodes

- Check updates: minikube update-check

- Stop cluster: minikube stop

- Delete cluster: minikube delete

Main concept: Minikube allows developers and students to create, manage, stop, and delete local Kubernetes clusters on macOS without requiring paid cloud infrastructure.
