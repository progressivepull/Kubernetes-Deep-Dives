# 7.3 Kubernetes security

**Kubernetes Security**

In this lesson, we learn how to protect Kubernetes clusters against security threats and malicious attacks.

Kubernetes clusters can be targeted by hackers who want to steal data, misuse computing resources, or disrupt services.

The instructor covers **three important Kubernetes security best practices**.

**1. Common Kubernetes Security Threats**

Hackers may target Kubernetes clusters to:

- **Steal data:** Access sensitive information stored inside the cluster.

- **Cryptocurrency mining:** Use your cluster's CPU and memory to mine cryptocurrency.

- **DDoS attacks:** Use compromised resources to launch distributed denial-of-service attacks.

**2. Add Security Context to Containers**

A Kubernetes Security Context defines security settings for pods and containers.

It helps restrict what containers can do if someone gains access to them.

The instructor recommends four important settings.

Example YAML:

yaml

securityContext:

allowPrivilegeEscalation: false

runAsNonRoot: true

capabilities:

drop:

\- ALL

readOnlyRootFilesystem: true

**Understanding Each Setting**

| **Setting** | **Purpose** |
|----|----|
| allowPrivilegeEscalation: false | Prevents processes from gaining additional privileges |
| runAsNonRoot: true | Prevents the container from running as root |
| capabilities: drop: - ALL | Removes Linux capabilities from the container |
| readOnlyRootFilesystem: true | Prevents modifications to the container's root filesystem |

**Why is this important?**

If an attacker gains access to a container, these restrictions limit what they can do.

For example:

- They cannot easily install additional software.

- They cannot modify the container's root filesystem.

- They have fewer privileges to perform malicious activities.

**3. Scan Kubernetes YAML Files with Snyk**

Another security practice is scanning Kubernetes YAML manifests before deploying them.

The instructor uses Snyk to identify security problems in Kubernetes configuration files.

**Run a Security Scan**

Use:

bash

snyk iac test deployment.yaml

This scans your Kubernetes manifest for potential security issues.

The instructor's initial scan identified six issues.

Examples included:

- Container running without a liveness probe.

- Potentially outdated container image.

- Writable root filesystem.

- Container running without user restrictions.

- Default capabilities not being dropped.

- Privilege escalation not being controlled.

**Fix Security Issues**

Add the security context configuration:

yaml

securityContext:

allowPrivilegeEscalation: false

runAsNonRoot: true

capabilities:

drop:

\- ALL

readOnlyRootFilesystem: true

Then scan the updated file:

bash

snyk iac test secure-deployment.yaml

The instructor's second scan reduced the issues from six to two.

The remaining issues were considered outside the scope of the lesson.

**4. Regularly Update Kubernetes**

The third security recommendation is to keep your Kubernetes version updated.

Why?

- Security vulnerabilities are discovered regularly.

- Updates provide security patches.

- Older versions may contain known vulnerabilities.

- Applying security updates helps protect your cluster.

The instructor recommends following the Kubernetes CVE (Common Vulnerabilities and Exposures) information.

A CVE identifies a publicly known security vulnerability.

**5. Additional Security Resource**

The instructor recommends the Kubernetes Hardening Guide published by the National Security Agency (NSA).

This guide provides additional recommendations for securing Kubernetes clusters.

Make sure to check for the latest version because security recommendations change over time.

**6. Three Kubernetes Security Best Practices**

**1. Secure your containers**

Use Security Context settings to restrict container privileges and filesystem access.

**2. Scan YAML manifests**

Use tools like Snyk to identify security misconfigurations before deployment.

**3. Update Kubernetes regularly**

Apply security patches and updates to protect against known vulnerabilities.

**Important Commands to Remember**

| **Command**                      | **Purpose**                            |
|----------------------------------|----------------------------------------|
| snyk iac test deployment.yaml    | Scan a Kubernetes YAML manifest        |
| kubectl apply -f deployment.yaml | Apply updated deployment configuration |
| kubectl get pods                 | Check running pods                     |

**Key Takeaways**

- Kubernetes security protects your cluster, applications, and data.

- Security Context restricts container privileges.

- Run containers as non-root whenever possible.

- Disable privilege escalation.

- Drop unnecessary Linux capabilities.

- Use read-only root filesystems.

- Scan YAML manifests with security tools like Snyk.

- Regularly update Kubernetes, especially when security patches are released.

- Use the NSA Kubernetes Hardening Guide for additional security recommendations.

**Main lesson:** Kubernetes security is not just about protecting the cluster. It's also about restricting what individual containers can do, identifying configuration weaknesses before deployment, and keeping your Kubernetes environment updated.

**Remember these three things: Secure your containers, scan your manifests, and update your cluster.**
